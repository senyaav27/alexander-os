# Alexander OS V15.8 | SenyaMarketing Theme + Google Sheets

## Что готово

- Фирменная тёмная тема: `#0F0F10` фон, `#17181A` карточки, `#313131` элементы управления, `#B9FD50` кнопки и прогресс.
- Действующие разделы «Главная», «Финансы», «Задачи», «Проекты», «Прогресс», прежний код и локальные данные сохранены.
- Новая кнопка Google Таблиц рядом с кнопкой `+`.
- Подключение Google Sheets через OAuth (без пароля Google, API-ключей и секретов в репозитории).
- Экспорт **только финансовой информации**: доходы, расходы, переводы между счетами, обязательства. У операций сохраняются IDs, чтобы повторная синхронизация не добавляла дубли.
- Удаления и правки операций отражаются пересборкой таблицы. Переводы записываются отдельно и **не считаются доходом/расходом**.
- Экспорт CSV для проверки без подключения Google.

## Публикация поверх текущего репозитория

1. Скачай ZIP и распакуй его.
2. На GitHub открой **senyaav27/alexander-os** -> **Add file** -> **Upload files**.
3. Загрузи из архива `index.html`, `brand-theme.css`, `brand-sheets.js`. Подтверди замену `index.html`. **Не удаляй другие файлы** репозитория.
4. Файл `ИНСТРУКЦИЯ.md` можно также загрузить, но для работы приложения он не нужен.
5. Открой GitHub Pages. Если установлена версия на экран «Домой», закрой её и открой заново. При необходимости очисти кэш сайта после создания резервной копии.

**Перед обновлением обязательно** в Alexander OS -> Настройки -> «Резервное копирование» создай зашифрованный `.aos` и отдельно сохрани его. ZIP не содержит личных данных.

## Подключение Google Таблиц (требует действий владельца)

1. Создай **отдельную приватную** Google Таблицу, например `Alexander OS - Финансы`. Не используй публичную таблицу.
2. В [Google Cloud Console](https://console.cloud.google.com/) создай проект, включи **Google Sheets API**.
3. Настрой Google Auth Platform / OAuth consent screen, добавь свой Google-аккаунт в тестовые пользователи, если приложение в режиме тестирования. Для статического сайта создай OAuth Client ID типа **Web application**.
4. В **Authorized JavaScript origins** добавь **точное происхождение** сайта, например `https://senyaav27.github.io` (без конечного `/` и без пути `/alexander-os`). Если у тебя кастомный домен, используй его происхождение. Google может потребовать корректные разрешённые домены и настройки экрана согласия.
5. Скопируй только **Client ID** вида `....apps.googleusercontent.com`. Client Secret не нужен и **не должен попадать в GitHub**.
6. В Alexander OS нажми кнопку Google Таблиц рядом с `+`, вставь Client ID и ссылку на приватную таблицу, нажми «Войти через Google» и выдай разрешение на работу с таблицами.
7. После успешного подключения появятся листы `AOS_Операции`, `AOS_Переводы`, `AOS_Обязательства`. Сверь количество операций и суммы с Alexander OS, особенно кредитные платежи.
8. Отредактируй одну тестовую операцию в Alexander OS, открой приложение и проверь обновление таблицы. Потом проверь удаление операции. **Не используй реальные личные данные в публичной таблице.**

## Важные ограничения

- Авторизация **пока не настроена**: для работающего подключения нужен твой OAuth Client ID, доступ к приватной Google Таблице и разрешение Google.
- Синхронизация запускается при изменении финансовых данных и работает, **пока открыта страница и действует OAuth-токен**. Закрытый iPhone/PWA не может запускать такую синхронизацию в фоне. При новом сеансе может потребоваться повторный вход.
- Не редактируй вкладки `AOS_*` как основной источник: синхронизация однонаправленная **Alexander OS -> Sheets** и перезапишет эти вкладки.
- Google API может не предоставить вход до корректной настройки OAuth. Встроенный браузер некоторых приложений может блокировать Google-авторизацию: открывай Alexander OS через Safari/Chrome.
- Текст финансовой операции (название и категория) отправляется в Google, но **никакие заметки, задачи, PIN-коды, пароли, другие разделы приложения и полные JSON-бэкапы не отправляются**.
- Долги и переводы сохраняются отдельно. При аналитике не складывай перевод между своими счетами с расходами, а погашение долга учитывай согласованной методикой, чтобы избежать двойного счёта.
- Содержимое вкладок включает личные финансовые данные, поэтому Google-таблица должна оставаться приватной. Описание архитектуры не является аудитом безопасности.

## ChatGPT + запланированные задачи

Подключи эту **отдельную** Google Таблицу к своему Google Drive в ChatGPT, затем проверь однократным запуском, что ChatGPT действительно может читать актуальные значения из листов `AOS_*`. До этого плановые задачи нельзя считать подключёнными.

**Еженедельно, Europe/Moscow:** «Прочитай актуальные финансовые данные Alexander OS из подключённой приватной Google Таблицы. За предыдущую календарную неделю посчитай доходы, расходы по категориям, изменение чистого потока, будущие обязательства. Не учитывай переводы как доход/расход. Проверь актуальность данных. Дай 3 конкретных вывода и одно следующее действие. Если источник недоступен, сообщи об этом, не выдумывай цифры».

**Ежемесячно, Europe/Moscow:** «По обновлённой финансовой таблице Alexander OS подготовь отчёт за предыдущий календарный месяц: доходы по источникам, расходы, чистый денежный поток, изменения по категориям, обязательства, динамика относительно прошлого месяца и цели накоплений. Отдельно укажи период последней синхронизации и ограничения полноты данных».

Плановые задачи **не создаются этим архивом**: настрой их отдельно в ChatGPT после проверки чтения Google Таблицы. Для отчётов без ручного повторного входа понадобится более устойчивый серверный механизм синхронизации, который не зависит от открытого браузера.

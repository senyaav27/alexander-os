## GATE 0

- Повреждённый JSON сохраняется без перезаписи. Постоянное предупреждение о сбое хранения; последняя сессия доступна для экспорта.
- Сравнение исходных байтов предотвращает перезапись из устаревшей вкладки при последовательных сохранениях. Это не распределённая блокировка.
- Импорт проверяет структуру, ID и финансовые суммы; сначала сохраняет оригинальные байты и backup текущей сессии; не объявляет успех при отказе записи.
- Sheets проверяет полный набор столбцов, ID и checkpoint предыдущей синхронизации. Одно атомарное `spreadsheets.batchUpdate` заменяет раздельные write/clear; затем полный readback. Pending checkpoint сохраняет ожидаемый результат; при неясном исходе записи автоматический повтор запрещён до сверки.
- Удаление удалённых строк приостановлено даже при наличии корзины. Восстановление/старый snapshot не дают права удалять Google-строки.
- Последние 50 результатов sync сохраняются локально в `aos_sheets_audit_v1`; не публикуются в GitHub.
- Sheets и brand CSS включены в precache; изменённые ресурсы версионированы. Пользовательские/старые кеши не удаляются при загрузке/активации.

Проверки: `node tests/gate0.test.cjs`; `python3 tests/gate0-browser.py`
(Chromium + Python Playwright, либо `uv run tests/gate0-browser.py`).
Синтаксис: `for f in *.js *.mjs; do node --check "$f" || exit; done`.
Тесты используют только синтетические записи; browser test открывает временный профиль и локальный сервер, не обращается к Google.

Осталось до закрытия GATE 0: настоящие iPhone/OAuth/Sheets, 7 дней наблюдения и процедура ручного разрешения конфликтов. Обновлённые клиенты сериализуют sync через атомарное создание уникального скрытого листа `_AOS_SYNC_LOCK_V1`. Проигравший клиент не пишет финансовые ячейки; после освобождения блокировки повторно сверяет checkpoint. Блокировка не имеет TTL и не перехватывается: при обрыве после начала записи/неверном readback остаётся до проверенного восстановления. Это сознательный отказ от доступности ради сохранности. Старые клиенты и ручные правки Google не соблюдают протокол: их нельзя использовать одновременно с sync. Блокировка не делает Sheets двусторонней базой и не объединяет изменения разных устройств.

### Ручная приёмка: iPhone и отдельная тестовая Google Таблица

Предусловия: отдельный HTTPS origin с тестовой сборкой PR #4 (его размещение требует отдельного разрешения), не origin рабочей PWA. Не удалять рабочую PWA и не очищать её данные. Только синтетика; отдельная таблица и отдельный тестовый OAuth client. Проверить Sync Rescue `15.8.7-gate0-review` в окне Google и appVersion в экспорте. Старые клиенты закрыть. До Google-тестов sync не подключать.

Базовый набор B0: использовать основной тестовый счёт A с 10 000 ₽; создать счёт B с 0 ₽. Расход 111 ₽ и доход 1 000 ₽ по A; перевод 500 ₽ из A в B; задача `G0-task` и заметка `G0-note`. Ожидается A=10 389 ₽, B=500 ₽, сумма=10 889 ₽; две операции и один перевод. Экспортировать B0 в «Файлы», убедиться, что файл открывается и ID уникальны. Quota/недоступное localStorage, обрыв после commit, частичный ответ сервиса и race в точной точке уже воспроизводятся автоматическими тестами. Не заполнять память рабочего iPhone ради этих сценариев. Если они дополнительно проверяются Web Inspector — только на отдельном тестовом origin, с заранее сохранённым B0.

При ошибке записи не закрывать текущую сессию/форму и не вводить операцию повторно; сохранить JSON и снимок сообщения. При неясном исходе Google и оставшемся lock не удалять его «для повтора»: остановить все клиенты, сохранить обе копии и отдельно сверить pending checkpoint/readback. Ручное снятие блокировки допустимо только после подтверждения отсутствия выполняющегося запроса и сохранности записей; автоматической кнопки обхода нет.
